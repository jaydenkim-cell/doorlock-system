# 채이 수학 — 기획서

초등 2학년 채이를 위한 수학·영어 학습 앱. Duolingo와 말해보카를 참고하되,
**두 앱 모두 대상 연령이 채이보다 한참 위**라는 점에서 출발한다.
메커니즘을 그대로 옮기면 역효과가 나는 지점을 하나씩 갈아 끼웠다.

| **곱셈구구 (2~9단, 72문항)** | 2-2 · 2단원 | 2학기 최대 관문이자 이후 나눗셈·분수의 전제. 문항이 유한해 "얼마나 익혔나"를 정확히 잴 수 있다 |

## 5. 학습 설계

### 5.1 간격 반복 (Leitner)

```
오답            → box 1 로 강등 + 이 판 끝에 재출제
정답 + 느림     → box 유지        (정답이라고 다 아는 게 아니다. 손가락으로 세는 중)
정답 + 빠름     → box + 1
```

| box | 다음 복습까지 |
|---|---|
| 1 | 같은 세션 안에서 다시 |
| 2 | 1일 |
| 3 | 3일 |
| 4 | 7일 |
| 5 | 21일 |

**마스터 판정 = `box ≥ 4` 이면서 `평균 응답시간 ≤ 목표(기본 3초)`.**
오래 기억하고 있고, 자동으로 나오는 상태를 둘 다 만족해야 한다.

### 5.2 문항 선택

한 판(기본 10문항)을 이 순서로 채운다.

1. 복습할 때가 된 것 (`dueAt` 지남, 오래 밀린 것부터)
2. 새 항목 — **한 판에 최대 3개.** 한꺼번에 몰아주면 초2는 무너진다
3. 약한 것 (정답률 70% 미만 또는 목표 시간 초과)
4. 그래도 모자라면 박스가 낮은 것부터

> 첫날처럼 복습할 것도 배운 것도 없으면 4번에서 새 항목으로 판을 채운다.
> 그때는 전부 보기 4개짜리로 나가므로 부담이 크지 않다.

### 5.3 오답 선지는 무작위가 아니다

정답 근처의 아무 숫자를 넣으면 "틀렸다"는 사실만 남는다.
실제 혼동 패턴으로 만들어야 **아이가 고른 오답이 곧 진단 데이터**가 된다.

**곱셈구구**
- 인접한 곱 — 7×8을 7×7 / 7×9로 (구구단을 외다가 한 칸 밀림)
- 반대쪽 인접 — 6×8 / 8×8
- 자릿수 뒤집기 — 56 → 65
- 덧셈 오적용 — 7+8 = 15

**받아올림·받아내림** (이 나이대 최다 실수는 단연 자리올림 누락)
- 받아올림 빠뜨림 — 37+48 → 75
- 받아내림 빠뜨림 — 45−18 → 37
- 자리마다 큰 수에서 작은 수를 뺌 — 45−18 → 33

부모 화면에는 "7×8을 세 번 틀림"이 아니라 **"7×8을 7×7과 헷갈림 (한 칸 앞)"** 으로 표시된다.

### 5.4 factKey 설계

덧셈·뺄셈에서 "37+48" 같은 구체적 문제를 키로 삼으면 경우의 수가 너무 많아 간격 반복이 작동하지 않는다.
그래서 키는 **실제로 걸려 넘어지는 지점인 일의 자리 계산**으로 잡는다.

```
37 + 48  →  핵심은 7+8  (받아올림)
45 − 18  →  핵심은 15−8 (받아내림)
```

같은 `7+8`을 여러 옷을 입혀 반복시키면서 숙련도는 하나로 추적한다.

## 5.5 난이도와 문제 형태 (3차 추가)

1차에는 난이도라는 개념이 없었다. SRS 가 *무엇을* 낼지는 적응했지만
**문제 자체의 어려움은 변하지 않았고**, 출제 순서에 셔플이 없어서
`allFacts()` 순서대로 2단 → 3단 행진을 했다. 몇 판만 해도 똑같이 느껴졌다.

### 문제 형태 6종

같은 사실 하나를 여섯 가지로 묻는다. **형태가 바뀌어도 `factKey` 는 그대로**다 —
`7 × ? = 56` 도 `7x8` 의 숙련도로 추적된다. 안 그러면 간격 반복이 통째로 깨진다.

| 형태 | 예 | 열리는 레벨 | 제약 |
|---|---|---|---|
| `basic` | `7 × 8 = ?` | 1 | — |
| `groups` | 🍓 4개씩 3묶음 | 1 | 곱 ≤ 20 (이모지 56개는 화면이 무너진다) |
| `skip` | `14, 21, ?, 35` | 2 | b ≥ 3 (앞에 두 항이 있어야 규칙이 보인다) |
| `missingB` | `7 × ? = 56` | 3 | 나눗셈의 준비 |
| `truefalse` | `7 × 8 = 56` O/X | 3 | 찍으면 50% — 가중치를 낮게 |
| `missingA` | `? × 8 = 56` | 4 | — |

`basic` 가중치를 가장 높게 둬서 익숙한 틀이 기준선으로 남고,
직전 문항과 같은 형태는 피한다 (연속 두 번이면 다양해진 느낌이 사라진다).

### 난이도 두 겹

**자동 레벨 1~5** — 최근 12문항의 정답률·속도로 오르내린다.
정답률 ≥ 0.9 이고 빠른 비율 ≥ 0.6 이면 +1, 정답률 < 0.6 이면 −1.
레벨은 **어떤 형태가 열리는지만** 정한다. 목표 응답시간까지 흔들면
"마스터 5단"이 무슨 뜻인지 알 수 없게 된다.

**부모 프리셋** — `자동`(1~5) / `쉬움`(1~2, 5초) / `보통`(2~3, 3초) / `도전`(4~5, 2.5초).
레벨 범위와 목표 응답시간을 함께 고정한다.

### 출제 순서

- 새로 배울 것은 `newFactOrder()` — 2 → 5 → 3 → 4 → 6 → 7 → 8 → 9단, 단 안에서는 섞음
- 큐를 최종적으로 셔플하되 **새 항목은 앞 70% 안에** 배치.
  아이가 지친 뒤에 새로운 걸 가르치면 안 된다

### 첫 판 진단

온보딩 직후 12문항(전부 보기 4개, 정오답 피드백 없음). 결과로 `mastery` 를 미리 채운다.
맞고 빠름 → 그 단 전체 `box 2` / 맞지만 느림 → `box 1` / 틀림 → 손대지 않음.

한 문항으로 그 단 전체를 추론하므로 정확하진 않다. 목적은 정확한 배치가 아니라
**아는 아이에게 2×1부터 가르치는 지겨움을 없애는 것**이고, SRS 가 몇 판 안에 바로잡는다.

## 5.6 용돈 저금통 (3차 추가)

한 판 끝내면 돈이 쌓이고, 목표를 채우면 부모 확인을 거쳐 현금으로 바꾼다.

| 적립 | 기본값 |
|---|---|
| 한 판 완주 | 10원 (하루 3판까지) |
| 한 단 마스터 | 100원 |
| 주간 목표 달성 | 50원 (주 1회) |
| 60초 랠리 최고 기록 | 20원 (하루 1회) |
| 목표 | 5,000원 |

설계에서 신경 쓴 것:

- **파밍 방지는 상한으로, 벌로 하지 않는다.** 쉬운 판 무한 반복을 막되,
  "정답률 몇 % 이상이어야 적립" 같은 조건은 두지 않았다. 그러면 어려워하는
  아이가 덜 받게 되는데 그건 정확히 거꾸로다
- **판수만이 아니라 실력에도 보상한다.** 판수만 세면 대충 빨리 넘기는 게 이득이 된다
- **현금 지급은 부모 잠금 번호 필수.** 번호가 없으면 아예 막힌다
- **속도를 숨기지 않는다.** 10원 × 하루 3판이면 5,000원까지 약 30주다.
  부모가 정한 금액을 말없이 바꾸는 대신, 부모 화면에 예상 기간을 띄우고
  12주가 넘으면 조정을 권한다
- **잔액은 실제 돈 약속이다.** 별이 사라지는 것과 돈이 사라지는 것은 무게가 다르다.
  적립·지급을 전부 내역으로 남기고 백업을 권한다

> 참고: 학습에 현금 보상을 붙이는 것은 내적 동기를 밀어낼 수 있다는 지적이 있다
> (과잉정당화). 다만 곱셈구구 암기처럼 원래 재미로 하지 않는 일에서는 습관을
> 붙이는 데 도움이 된다는 쪽이 우세하다. 그래서 보상을 **판수보다 마스터에**
> 무겁게 실었다.

## 5.7 여러 아이 · 학년 (4차 추가)

### 프로필

데이터 구조는 1차부터 아이별로 나뉘어 있었지만(진도·숙련도·레벨·저금통·설정이
전부 `data[profileId]` 안), **그걸 쓸 UI가 없었다.** `setActiveProfile()` 은
어디서도 불리지 않았고 온보딩은 프로필이 0명일 때만 떠서, 채이 프로필이 생긴
뒤로는 둘째를 추가할 방법이 없었다.

- 앱을 켤 때 아이가 2명 이상이면 **"누구야?"** 화면 (`screens/who.js`)
- 홈 왼쪽 위 얼굴을 눌러 전환 (아이도 쓰는 버튼이라 잠금 없음)
- 부모 화면에서 추가 / 학년 변경 / 삭제
- 삭제는 진도와 **저금통 잔액까지** 지운다. 잔액이 남아 있으면 금액을 보여주며
  한 번 더 묻는다 — 실제 돈 약속이다

> **여기서 실제 버그를 하나 잡았다.** `createProfile()` 의 id 가
> `'p' + Date.now().toString(36)` 뿐이라 **같은 밀리초에 만든 두 아이가 같은 id 를
> 받아 데이터 버킷을 공유했다.** 부모가 아이 둘을 연달아 추가하면 진도가 통째로
> 섞이는 문제였다. 무작위를 섞고 충돌 시 다시 뽑도록 고쳤다(`uid()`).

### 학년 (초1~3)

3차까지 `grade` 는 이름표였다 — 온보딩에서 2로 고정되고 홈에 글자로만 보였다.
이제 `js/grades.js` 가 학년별 차이를 한 곳에 모은다.

| | 초1 | 초2 | 초3 |
|---|---|---|---|
| 곱셈구구 | 잠금 (아직 안 배움) | 열림 · 메인 | 열림 · 메인 |
| 받아올림·받아내림 | **한 자리** `7 + 8` | 두 자리 `37 + 48` | 두 자리 |
| 홈 메인 지도 | 받아올림 (2칸) | 구구단 (8칸) | 구구단 |
| 기본 난이도 | 쉬움 | 자동 | 보통 |
| 진단 판 | 덧뺄셈으로 | 곱셈구구로 | 곱셈구구로 |

구현은 `addsub.dress()` 가 십의 자리를 입히는 부분을 건너뛰는 것(`opts.plain`)이
전부다. 오답 선지와 진단은 그대로 쓴다 — 한 자리에서도 `정답 − 10`(받아올림
빠뜨림), `정답 + 10`(받아내림 빠뜨림)이 여전히 실제 오류 패턴이다.

**초4 이상은 넣지 않았다.** 나눗셈·분수 생성기가 없어서 곱셈구구를 아는 아이에게는
금방 지루해진다. 2장 11번(고학년까지 확장의 함정)과 같은 이유로, 전 학년을
어중간하게 덮느니 초1~3을 제대로 하는 편을 골랐다. 온보딩에 그렇게 적어 둔다.

### 부모 잠금은 필수 (배포 전 하드닝)

배포하면서 두 가지를 잠갔다.

1. **첫 실행에 잠금 번호를 반드시 정한다** (`screens/lock.js`).
   부모 리포트 · 난이도 설정 · 아이 추가/삭제 · 현금 지급이 전부 이 뒤에 있다.
   **진짜 위험은 낯선 사람이 아니라 이 기기를 쓰는 아이다** — 잠금이 없으면
   아이가 난이도를 쉬움으로 바꾸거나 자기 저금통을 현금 처리할 수 있다.
2. **개발용 훅(`window.__chaeyi`)을 배포본에서 닫았다.**
   열려 있으면 개발자도구에서 `allowance.adjust(999999)` 한 줄로 잔액을 만들 수 있다.
   로컬(테스트)과 `?debug=1` 에서만 열린다.

**아이는 스스로 등록할 수 없고 부모만 추가할 수 있다** — 이 기기에서의 승인제다.

막지 못하는 것도 분명히 해 둔다. 다른 기기에서 주소를 열면 그 기기는 처음부터
새로 시작한다. 기록이 서로 보이지 않으므로 **새는 정보는 없지만**, 접근 자체를
막지는 못한다. 서버 없이 그것까지 막으면 흉내만 내게 되고, **막는 척하는 잠금은
없느니만 못하다** — 안심하게 만들기 때문이다. 진짜 승인제는 계정·서버가 필요하고
그러면 개인정보 저장·법정대리인 동의·오프라인 불가가 함께 따라온다.

### 저금통 아이별

금액 설정은 이미 아이별이었다(`settings` 가 `pdata()` 안). `enabled` 스위치만
추가했다. 프로필을 만들 때 물어보고, 꺼두면 홈·결과에서 저금통이 사라지며
적립도 되지 않는다. **놀러 온 친구까지 용돈을 벌 필요는 없다.**

## 6. 게임화 (초2 친화 버전)

- **하트 없음.** 틀리면 정답을 보여주고 이 판 끝에 한 번 더 낸다
- **구구단 지도** — 2~9단 8칸이 숙련도만큼 아래에서 차오른다. 100%가 되면 초록 + ⭐️
- **주간 도장** — 월~일 7칸, 목표 4일. 리셋 없음, 매주 새로 시작
- **보상** — 세션 완주 = 별 / 한 단 마스터 = 스티커 / 자기 최고 응답시간 갱신 = ⚡️
- **콤보** — 3·5·10 연속 정답에서 반응이 커진다. 세션 헤더에 🔥 카운터
- **60초 랠리** — 60초에 몇 개. 겨룰 상대는 어제의 자기 기록뿐.
  **틀려도 box 를 강등하지 않는다** — 속도 게임에서 벌을 주면 하트를 없앤 이유와 모순된다
- **정답은 0.85초 만에 자동으로 넘어간다.** 리듬이 끊기면 재미가 사라진다
- **오답은 아이가 직접 눌러서 넘어간다.** 정답을 한 번은 보고 지나가도록

## 8. 데이터 모델

```js
profile  { id, name, grade:1|2|3, avatar, createdAt }    // 배열. 아이마다 아래가 통째로 분리된다
mastery  { skillId, factKey, box, dueAt, seen, correct,
           avgMs, lastWrong, wrongLog[] }                // SRS + 응답시간 + 오답 진단
session  { id, skillId, groupId, queue[], retryQueue[],
           items[{factKey, given, correct, ms}],
           index, question, questionStartedAt }          // index/question 저장 → 중단 복구
settings { weeklyGoalDays, sessionLength, targetMs, maxNewPerSession,
           difficulty, allowance, sound, haptics, parentPin }
levels   { [skillId]: { level:1..5, recent[] } }         // 자동 난이도
rally    { [skillId]: { best, last, at } }               // 60초 랠리 기록
wallet   { balance, lifetime, ledger[{at,kind,amount,note}] }  // 용돈 저금통
```

`schemaVersion`과 마이그레이션 훅(`state.js`)을 처음부터 두었다.
필드를 늘려도 아이가 쌓은 기록을 버리지 않기 위해서다.

## 9. 성공 지표 (4주 뒤 측정)

"재미있는 앱"은 측정할 수 없으므로 숫자로 고정한다.

1. 채이가 **부모가 시키지 않고 켠 날** 수 — 목표 4주간 10일 이상
2. 곱셈구구 평균 응답시간 — 5초 → **3초 미만**
3. 세션 완주율 — **80% 이상**
4. 마스터한 단 — 8단 중 **5단**

1·2·3은 부모 화면에서 바로 읽을 수 있고, 백업 JSON에 원자료가 들어 있다.

## 10. 로드맵

**1차 (완료)** — 곱셈구구 + 받아올림·받아내림, SRS, 부모 리포트, PWA

**2차 — 영어.** 여기서 가장 흔한 오해를 먼저 정리해 둔다.

- 공교육 영어는 **초3부터**다. 채이는 **영어 글자를 못 읽는 전제**로 설계해야 한다.
- 말해보카식 단어 암기는 대상 연령이 한참 위다. 가져올 수 있는 건 간격 반복과 세션 구조뿐.
- 초2 영어 = 파닉스(자모 소리) + 사이트워드(Dolch pre-primer 약 40단어) + 듣고 고르기.
- **지시문과 보기를 전부 음성으로 내보내야 한다.** 단어마다 오디오와 그림이 필요해
  수학 대비 공수 약 5배. 여기가 이 앱이 죽을 수 있는 지점이다.
- 오디오는 Web Speech API(무료, 기기 내장 TTS)로 시작하고, 품질이 부족하면 녹음으로 교체.

**3차 (완료)** — 문제 형태 6종, 자동 난이도 + 부모 프리셋, 출제 순서 셔플,
첫 판 진단, 콤보, 60초 랠리, 용돈 저금통

**4차 (완료)** — 프로필 여러 개, 학년별 콘텐츠(초1~3), 저금통 아이별 on/off

**5차** — 시각과 시간(아날로그 시계 UI), 길이, 표와 그래프

**언제든** — 채이 옆에서 5분 관찰. 기획서 10장보다 낫다.
